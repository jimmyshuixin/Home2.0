# 创作工作流、摄影筛选与专题

延续现有纸墨界面、Nuxt/Vue、Workers、R2 和不可变发布快照。此阶段承接 `EXPERIENCE-20260930.md` 的编辑器原型，采用经过旧稿契约适配的 Tiptap 3.31.3；不增加付费编辑器、搜索或数据库服务。免费服务仍受现有用量额度限制。

## 写作与恢复

- 创作、相册、健身和歌单的已保存记录，在停止编辑 30 秒后自动保存草稿。首次新建仍需主动保存，防止网络中断后的重复创建。保存与发布继续分开。
- Tiptap 只输出现有 `RichTextDocument` JSON。旧稿的嵌套列表、内联 code 与其他 marks 共存、重复 marks 均有适配；每次修改受原契约验证。支持撤销、重做、标题、列表与安全链接。粘贴统一为纯文本，中文合成期间不触发保存。
- 本机恢复副本按管理员、内容和编辑标签页隔离。发现副本时先让作者选择；较旧版本要求手动核对。登录过期、保存失败或版本冲突会暂停自动保存，保留本机编辑并允许导出 JSON。副本有大小、数量和有效期限制，不能替代服务器保存；退出账户会清理该账户的本机副本。
- 保存回执仅确认发出时的内容，随后产生的编辑继续保持未保存状态。历史恢复期间锁住编辑区，同时保留可能异步到达的新编辑。
- 历史面板可分页、查看变化、预览和恢复。恢复创建新的草稿版本，原历史版本与公开 release 均保留。恢复同样验证 expectedVersion 和媒体生命周期。
- 新修订通过不可变前驱链读取。旧记录没有历史索引，需逐批查找；一次仅处理有限批次，可能出现空批次。Firestore 的分页 lookahead 也计入实际读取用量，不承诺完整历史只需一次读取。

## 全部照片

`/photography?view=photos` 汇集公开相册中的照片，按拍摄年份、相机、镜头、焦距组合筛选，每页 24 张。筛选和页码进入 URL，可以复制当前选择。

年份优先采用作者校正的照片日期，其次为许可的真实拍摄日期；不用上传时间替代。缺失信息显示为未记录。器材名称仅规范字形、大小写及标点差异，保留镜头小数光圈的区分。

灯箱保留图注、许可 EXIF、原相册链接和原照片点赞标识；跨相册重复照片 ID 使用内部组合键，避免串图。筛选索引明确投影字段，不携带地点、原图地址或原始 EXIF。复制链接只含公开筛选条件，不携带私有预览参数。

## 专题与有序系列

网站设置中可添加专题，填写名称、链接名称、引言，选择创作与相册并排序，最后启用。专题与网站设置一起发布；加入尚未公开内容时，需要在同次发布清单中选择相应内容和网站设置。

只根据候选发布快照解析成员。禁用、无公开成员的专题不进入公开数据；草稿、隐藏或不存在的成员不进入页面、索引和 sitemap。完整编排继续留在后台草稿中。上限为 24 个专题，每个 100 项。

公开路径为 `/topics` 和 `/topics/<slug>`。详情页有所属专题及前后项导航，封面、标题均解析自同一公开快照。有公开专题时才显示页脚入口；没有专题时不会自动编造或发布示例。改名通过稳定专题 ID 保留旧链接跳转，隐藏时清理失效跳转。

## 验证与发布

运行 `npm run check`、`npm run test:unit`、`npm run test:publication`、后台构建、Worker dry-run 和 Python collector 测试。Nuxt generate、dev、typecheck 和 prepare 都会执行配置并写入 `.data/site.json`；这些命令必须串行执行，不能在同一检出并发运行。

本地合成夹具覆盖保存并发、断网恢复、版本冲突、历史恢复、组合筛选、分页、空结果、跨类型专题导航和手机布局。浏览器 composition 事件测试不等同于所有系统中文输入法候选窗均已验证。

正式交付沿用现有发布流程：记录部署前公开数据，推送代码并通过 CI，部署 Worker 和后台网关，按 `changes: []`、`rebuildPublished: true` 重建当前公开内容，私有预览验收后激活，退出预览并匿名复核。保留所有未发布草稿，不将本地测试夹具带入生产。
