# 请求恢复与生产维护补验

本轮针对第二阶段验收留下的维护未完成、公开请求偶发中断和抖音公开同步失败进行修复。不能把一次重跑成功当作原故障不存在；历史失败证据继续保留。

## 公开页面请求

`apps/web/lib/api-request.ts` 为一次请求设置覆盖响应头与 JSON 正文的 15 秒截止时间。只对可恢复的 GET 失败重试一次，间隔 300 毫秒；连续两次超时约 30.3 秒后给出重试提示。用户取消与组件卸载会结束当前请求和退避等待，不误显示为超时。认证、限流和其它明确不可重试状态不自动重试，写请求不自动重放。

留言分页失败时保留已读留言与原分页游标，点击重试继续失败页。切换评论目标时取消旧请求，旧响应不能覆盖新目标。首页原有弹幕暂停/继续、减少动态效果支持与纸墨字体保持原行为。

留言 GET 共用发布版本和预览鉴权检查。全站留言只需当前发布标识，省去完整内容快照读取；作品和相册留言用既有、按发布版本分区的公开内容缓存验证目标存在性。评论内容仍实时读取，隐藏/审核操作不依赖旧缓存过期。管理员预览不使用公共内容缓存。

## 抖音公开资料同步

收集器保留有限的异常原因链类型及允许的网络错误码，诊断不包含错误原文、访问 URL、Cookie、令牌或浏览器存储。匿名初始化仅对明确的临时导航超时/网络错误最多额外尝试一次；未知后端错误、登录要求、风控或限流继续失败退出。复用相同的匿名临时配置，无代理切换、登录信息或访问限制绕过。

收集器仍在独立的 GitHub Actions job 内运行，不持有站点凭据和 OIDC 权限。可信导入器只处理清洗后的公开数据，失败保留上一份成功数据及其时间。定时工作流依赖 `main` 的精确代码，网站构建依赖 `codex/v3-production`；发布此修复必须分别确认两个代码入口，不能只部署 Worker 就宣称同步已升级。

## 验收边界

本地回归覆盖慢响应正文、取消、有限重试、禁止重放写请求、评论分页、公开/预览隔离，以及异常包装与诊断隐私。真实开发浏览器用隔离故障服务验证恢复；这些注入案例不写入生产内容。

生产维护只处理既有允许集合的到期技术记录，保持原租约、192 步每日预算与保守用量预留。需真实确认三类历史记录回填完成、到期查询成功、完整轮次结束与冷却状态。R2 盘点和历史发布仍只读。

发布后以新匿名浏览器上下文验证桌面/手机首页和留言页，核对新版本、实际留言响应、弹幕操作、字体资源及控制台；另核对公开数据哈希、真实分页与所有公开页面。保留失败尝试，不通过取消断言来取得通过结果。生产 SHA、发布标识、工作流运行及聚合维护回执保存在工作区交付证据目录。

外部链路仍可能出现连接关闭或延迟。修复提供有界恢复和明确错误状态；一次成功验收不构成对网络或外部平台持续可用性的保证。
