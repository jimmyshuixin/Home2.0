# 第二阶段：到期记录维护与存储盘点

本阶段沿用现有存储与后台认证，在“维护”页提供有界清理和只读存储盘点。代码合入、部署成功、生产维护完成是不同状态；交付记录需分别核验，不用本文件代替生产证明。

## 到期记录清理

自动清理只覆盖 `sessions`、`rates`、`idempotency` 三个集合。它不删除留言、私信、草稿、修订、发布、媒体，也不处理上传/发布的恢复凭据或 `auth_epochs`。

Firestore 文档保留原 `record_json`，在同一次写入中投影数值 `expires_at`，使用单字段索引查询。它不是 Firestore 托管 TTL；后者不在免费用量范围内。Memory/SQLite 和 Firestore 具有相同的到期查询与事务语义。

首次运行分批回填旧记录，每次最多 5 条；回填后轮流清理三类记录。每次重新在事务内读取源记录与当前时间，续期记录保留，到期值异常的记录保留并计数。事务内批量读取减少上游请求。检查点、删除计数和删除操作一起提交；外部查询不在可重试的事务回调中执行。

运行使用持久化租约及每日预算。同一时间只有一页获得执行权；不确定的提交与失败不退还本步预算，避免失败重试无限消耗资源。过期租约允许后续调用续跑，不把失败当成成功。

- 自动调度：UTC 每小时第 7、22、37、52 分钟执行一页，保持原有统计清理与公开资料同步的独立调度。
- 每日最多 192 步，管理员手动推进和定时任务共用预算。每步最多 5 条；自动调度理论上最多处理 480 个候选/日，实际吞吐受回填、空页、失败和冷却影响。
- 每步预留 42 个读取单位、7 个写入单位和 5 个删除单位，累计上限分别为 8064、1344、960。它们是本模块的保守预算，不是整个项目的账单或免费额度剩余；状态读取、认证、其他业务和竞争读取另计。
- 正常清理完整轮次没有更多候选时冷却一小时。过期不代表立即物理删除，历史积压可能需要多个预算日。
- 预算日只向更晚的 UTC 日期推进，时钟回拨不会重复领取额度。

公开留言/私信的提交凭据可到期，但业务记录永久保留其独立生命周期。删除凭据后再次使用旧请求键，若原业务记录仍在，API 返回 `IDEMPOTENCY_EXPIRED`，不会覆盖审核状态、正文或重复计数。

## 后台操作

打开“维护”，先刷新状态。“推进一批”处理一页；连续运行逐次等待响应，可在当前批次结束后暂停或离开。后台显示保留的进度、异常记录数量和预算状态。遇到正在处理或租约未过期，按页面给出的时间稍后刷新；不要把等待状态当作清理完成。

异常到期记录只提供聚合计数，不公开会话 ID、令牌、CSRF 或请求正文。它们需要后续独立核查；本功能不会猜测无效时间。

## R2 存储盘点

“开始盘点”创建可续跑任务。每步最多执行一次 R2 `list`（100 个对象）或一页发布记录查询（5 条）。对象列表直接提供字节数，不读取媒体内容、不逐对象 HEAD。当前公开指针仅在必要步骤单独读取并限制大小。

分账覆盖：原始媒体、派生媒体、发布文件、私有发布快照、其他对象。每轮有对象页数、发布记录数和执行次数上限；每个 UTC 日还有独立的盘点预算。达到边界时显示“部分统计”，不把未扫描项视为不存在。

任务通过版本号和租约防止两个浏览器、重复响应或暂停后的旧请求重复累计。外部列表读成功后，结果仅在相应任务与租约仍匹配时提交。失败保留上次检查点，管理员可重试。后台和日志不暴露底层对象键、存储元数据或私有正文。

盘点提供的是扫描时间窗口内的已完成对象 payload 总量。并发上传、覆盖、删除可能影响结果；未完成的 multipart 分片不在内；字节总量也不等同于 GB-month 账单、账户总量或免费额度剩余。现有媒体已用/预留账本继续按原规则工作。

## 历史保留建议

盘点同时生成逐版本保留建议，默认最近 5 个可预览或已发布版本，可选择 3–10 个；连续失败的构建不会挤掉成功版本的保留名额。保护扫描首尾观察到的公开版本、尚在构建/等待启用/切换/对账的任务及这些最近版本。旧 `live` 状态不等于现在的公开指针。

`previousReleaseId` 只列出观察到的前序关系；本次没有完成所有媒体、历史修订和快照内容的引用闭包审计。每条建议的 `deleteAllowed` 都是 `false`。“供人工审查”不表示已经证明可安全删除。后台没有删除历史版本按钮，也没有针对 release 路径配置时间到期删除规则。

下一步实际回收需要明确固定版本、归档/恢复手段、并发发布保护与引用闭包，再建立单独的可确认回收流程。发布容量预留和全账户账单对账也未由只读盘点自动解决。

## 验证与运维

新路由都位于 `/api/v1/admin/maintenance/`，使用既有管理员会话、Origin 和 CSRF 校验；状态响应 `no-store`。需要测试未登录、错误 Origin、缺少 CSRF、版本重复、续期竞争、提交响应丢失、过期租约、预算耗尽、时钟变化及未知对象归类。

测试覆盖真实本地 Miniflare R2、SQLite/MemoryStore、Firestore 请求契约及后台桌面/手机交互。生产只执行受控的到期记录维护和只读盘点；不以真实内容作删除试验。部署前运行三套类型检查、完整测试、管理端构建及 Worker dry-run，部署后核验代码 SHA、后台结果、原公开数据哈希与匿名页面。

官方依据：[Firestore 免费用量边界](https://firebase.google.com/docs/firestore/quotas)、[R2 列表与游标语义](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[Workers 调度和资源限制](https://developers.cloudflare.com/workers/platform/limits/)。平台限制以当前账户与官方文档为准，程序预算不是无限免费承诺。
