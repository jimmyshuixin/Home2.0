# 2026-09-29 可靠性升级

本轮修复源码审查发现的操作与一致性问题，沿用现有纸墨界面、Workers Free、R2、Firestore 和 GitHub Actions。此文说明代码行为及验收方法；提交本身不是生产发布证明。

## 行为变化

- 上传队列暂停后继续会恢复当前有原文件的暂停项；认证恢复同样适用。已确认分片和上传会话复用，真实文件错误仍需单独重试。
- 保存响应绑定到发起操作的栏目、编辑器和页面。保存期间切到摄影或设置后，旧响应不会跳错页、打开错误发布选择或清掉新页面的未保存提示。
- 新粘贴的纯文本按换行生成 `hardBreak` 和段落，保留插入点前后的内容。历史已保存文本不会被此改动自动迁移。
- 只选择或清除头像也会触发未保存保护。公开页如何消费头像、站点标题、主题设置属于后续功能工作。
- 退出、修改密码、确认密码重置时清除管理员预览 Cookie。失效身份仍不能读取私密候选。
- 公开评论索引完成后按目标和创建时间降序读取，遵守 1–50 的 `limit`（默认 20；首页请求 12），相同时间使用 ID 稳定分页，游标绑定目标。详情见 [存储文档](../../workers/api/src/store/README.md)。
- 处理失败的媒体可以经回收站、完整引用检查和确认，逐步中止已知分片并删除受控对象，最终在同一事务释放原件占用和衍生文件预占。重复调用、响应丢失和旧执行器返回不会重复释放容量。历史修订和发布仍受引用保护。

## 评论迁移

部署新 API 与管理端后，在“评论审核 → 更新留言索引”执行回填。每次服务端请求最多处理 5 条，浏览器顺序推进并允许暂停、重试；离开后保留已完成进度。迁移期间继续使用旧的有界读取路径，并返回 `meta.catalogReady=false`，不得把这时的排序或首页完整性标记为已修复。

完成后需看到 `ready=true`，并匿名检查首页 `limit=12`、留言页分页和合法目标过滤。Firestore 读取包含一次索引状态读取和一次 `runQuery`，后者最多读取 `limit + 1` 条；不需要新增复合索引。不要在 ready 后直接回滚到不维护评论投影的旧 API，避免后续审核与索引不一致。

## 失败媒体清理边界

这不是自动全库清理。管理员应先查看失败记录，再移入回收站、检查全部引用、确认永久删除。恢复会先冻结原处理任务，完成所有已知 multipart abort，再逐对象验证身份、删除并确认不存在，最后释放额度。清理完成后重新上传会创建新资产。

仍有活跃上传或合并请求时暂不能开始；初始化结果不明、缺少 multipart 句柄、对象与账目不一致时保留文件和容量，提示人工核对。此改动不猜测遗失句柄、不删除仍被历史版本引用的媒体，也不自动回收整桶历史发布。

## 依赖与检查

Vite 固定为 7.3.5，覆盖 esbuild 为 0.28.1、undici 为 7.29.1；`package-lock.json` 同步更新。覆盖项须在未来升级其上游包时重新审查并尽量移除。漏洞审计是执行时的已知公告快照，不能代替测试或保证未来无漏洞。

`npm run check` 同时检查 API/契约/执行器、管理端和公共页面。`test:unit` 限制为两个 worker，`test:publication` 独占构建输出；Vitest setup hook 超时为 30 秒。PR 工作流还运行 Python 数据转换测试和管理端构建。工作流不部署、不获取生产 OIDC 权限、不公开上传私有构建产物；分支保护并未由此自动开启。

真实后台交互回归可先构建管理端，然后在独立终端显式启动本地夹具：

```powershell
$env:XVYIN_UI_FIXTURE='1'
node --import tsx apps/admin/tests/browser-fixture.ts
```

另一个终端执行 `node apps/admin/tests/browser-reliability.mjs`。它仅使用本地测试身份和内存数据库，测试延迟保存、粘贴、头像保护及上传暂停恢复，不接触生产账号。可用 `XVYIN_TEST_BROWSER` 指定 Chromium 浏览器路径，`XVYIN_QA_OUTPUT` 指定证据目录。

## 发布验收

按顺序记录源码 SHA、代码部署、评论索引 ready、候选生成、私密预览、公开激活和匿名回读。内容重建保持 `changes: []`，对比五类公开 API 的 `data` 哈希，检查页面发布标记、静态资源与无预览状态。生产媒体不会作为破坏性测试样本。

后续优先项是会话/限流/幂等记录的有界到期清理、历史发布存储预算、公开设置消费、全文检索和摄影浏览；它们没有在这批变更中冒充完成。
