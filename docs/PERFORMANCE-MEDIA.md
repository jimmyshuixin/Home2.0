# 性能与媒体管理说明

本改动沿用独立 API Worker、Pages 管理端和私有 R2 内容存储，不新增付费套餐、图片服务或数据库。公开内容仍通过候选预览后切换版本。

## 媒体管理

- 在“媒体”页按文件名搜索整个目录，组合文件类型、处理状态、分类筛选；可选最新/最早、文件名升降序、实际占用空间升降序。分类留空表示未分类。
- 回收站暂时移除媒体选择器中的条目，保留现有引用和实际文件；恢复可再次选用。回收站仍占用容量。
- 永久删除先分步检查草稿、设置、所有历史修订及发布快照。仍有引用时列出来源并阻止操作。检查通过后须单独确认；逐个删除 R2 原件及衍生件，完成后只结算一次容量。
- 检查阶段最多保留 15 分钟，并暂缓内容保存/发布；关闭可取消。确认清理后立即释放全局锁，其他内容可正常编辑。已确认清理可继续，已删除媒体不能被旧编辑器重新引用。
- 处理中媒体不可删除。失败处理若仍有未释放的预留或未确认分片，不会伪造“已释放容量”；需要先核对处理任务。
- 旧目录首次打开时按每批 5 条完成投影，不把不完整索引显示成空库。筛选每次扫描最多 48 条，返回最多 24 条；没有匹配但存在后续页时显示“继续查找”。

## 上传与传输

文件 SHA-256 校验在独立 Web Worker 中执行，避免大文件校验持续占用界面线程。分片保留 5 MiB，最多两个并发；只对网络失败、限流和服务错误有限重试，重试不重复已确认分片。

已验证且仍可用的同 SHA-256、同大小、同类型文件直接复用。创建请求用幂等回执防止丢回复后的重复任务和重复预占，恢复信息保留原请求标识。若 R2 初始化结果无法确认，保留一次预占并报告待核对状态，避免盲目创建更多孤立上传。文件完成后转码派发失败的重试继续使用原上传。

现有图片 384/960/1600 WebP、H.264/AAC 和 MP4 faststart 管线继续使用。前台按实际显示尺寸选择已有图片版本，懒加载下方图片；音视频保持按需加载和统一播放协调。

## 公开缓存

每次匿名请求仍读取 active-release.json，确认当前公开版本；索引和小正文以版本号加真实对象键缓存到 Cloudflare Cache API。私密预览、管理员文件、活动版本指针不进入共享缓存。

- 内部索引上限 4 KiB，完整正文上限 2 MiB，公开 JSON section 上限 1 MiB。
- 大视频和冷 Range 请求直接流式读取 R2；不为填充缓存读取完整大文件。
- HEAD 只取元数据；正确支持 ETag、Last-Modified、304、206、416 和 If-Range。
- 浏览器保留重新验证，减少隐藏/撤回内容的额外缓存延迟。边缘缓存失败不影响回源。
- QQ 已验证曲目目录缓存 5 分钟；签名播放地址、307 和带本次 nonce 的解析页不缓存。每次先确认歌单仍在当前公开配置中。
- Nuxt 改为链接交互时预取，减少首次访问下载未打开页面；音乐初始化减少一次串行配置请求；健身计数按可信上海午夜刷新，替代每分钟轮询。

Cache API 是数据中心本地缓存，不承诺所有地区都已经热缓存。线上体验受用户网络与服务商链路影响，本地测试不代表大陆各运营商表现。

## 费用与容量口径

单文件上限维持 512,000,000 字节，媒体总上限维持 10,000,000,000 字节。媒体配额包含原件、衍生件与预占；历史页面构建和快照仍会额外占用 R2 存储，不应把媒体仪表盘当作整个账户的账单。

免费层仍有请求次数、CPU 和存储配额；本改动通过边缘缓存、复用文件和拆分操作降低消耗，没有购买套餐。R2 免费存储按 GB-month 计量，超过免费额不是无限免费。操作方应以 Cloudflare 实际账户用量核对整个桶容量；本版本不自动清除已有历史版本或用户数据。

## 代码更新与发布

发布中心“发布记录 → 重新生成当前公开页面”仅使用当前公开快照，保留 revisionId、publishedAt 和所有草稿。先生成并预览，再确认切换公开版本。后端拒绝把草稿变更与 rebuildPublished 模式混合，也拒绝基于过时的 active ID 发布。

## 验证

针对性单元/集成测试覆盖缓存失效与私密边界、R2 条件/范围读取、媒体筛选分页、并发删除与编辑、实际 R2 删除和一次性配额结算、上传幂等恢复，以及公开快照重建不夹带草稿。管理端浏览器验收使用独立合成数据，不删除现有用户媒体。部署编号与线上实测另记录于本次工作目录 performance-media-qa。
